# Timed processor and audio acceptance

Proposed tests for RENDER-03/04. Execute after the timed contract and its adapters are approved. Keep the test clock, valid source intervals and output mapping explicit. Tests are unrun.

| ID | Scenario | Expected observation |
|---|---|---|
| TIME-map | Use a 24000/1001-rate composition with negative start, a source at a different rate, stretch, reverse and a non-monotonic remap. Request frame center, adjacent samples and subframe shutter positions. | Compute exact host time and sample identity under each named domain. Confirm source intervals, hold/interpolate and boundary outcomes against a literal test table. No dependence on floating rounding around frame edges. |
| TIME-neighbors | Use the temporal denoiser against a known ramp, and a layer with source bounds inside its composition. Request an ROI and neighbors outside the source at both ends. | Region and spatial/temporal extent are jointly authorized. Boundary policy applies in the declared domain; the app never changes it silently. Legacy v2 migration preserves its clipped or absent behavior as evidenced. |
| TIME-state | Simulate a seeded accumulator in forward, random, reverse and parallel requests. Reopen with a matching and a stale checkpoint. Change one historical input. | Matching final results have identical seeds and dependency digests. Reconstruct from valid initial state or checkpoint. Expanded work is bounded; a stale checkpoint cannot produce complete output. |
| TIME-invalidate | Change one frame, source remap, shutter setting and parameter segment in separate runs. Exercise a normalized zero-sum dependency cycle and an allowed acyclic future edge. | Correct inverse-mapped affected intervals, no incomplete frames cached as exact, and typed refusal of invalid recursion. Conservative invalidation has an explicit bounded fallback. |
| TIME-edit | Register a procedural clip, transition and custom view. Use the actual timeline to select, trim, retime and move it, then save/reopen and export. Try a package with an unsupported native track role and a compatible visual role. Edit the displayed frame without seeking. Sample both original and altered mode. | One app timeline, exact edited content and Undo, with capability-level availability. PC's supported timeline semantics and EC's composition semantics are reported distinctly. |
| AUD-format | Mix a sample-rate conversion, an impulse and a two-input test effect with declared lookahead and channels. Scrub around a reverse, loop and position discontinuity. | Host sample indices, layouts, latency compensation and automation line up with the expected samples. Match offline outputs without block-size-dependent timing. |
| AUD-device | Stall a worker across a real playback deadline. Then seek, restart, change rate and revoke at a full ring. Fail open and stream play separately. Suspend and swap a device with a pending cutover. Stall scrub decode. | Device callback takes no guest work or wait. Playback uses a documented fallback and records underflow; device clock and content clock follow defined policy. Late blocks do not return. No stranded feeder. Verify final audible sample and recovery after device loss. |
| AUD-exact | Launch exact headless AAC, Opus and standalone PCM exports with Auto on for procedural audio. Make one required decode fail after earlier packets, then substitute intentional silence. | Complete compatible fallback or explicit failure. No silent playback substitution enters a final file. Audit final audio and frame sync and preserve an existing file on failure. |

Hypothesis: at 48 kHz with 128-frame blocks, Store reuse plus checkpoint ≤ 10% of the block budget. It measures one warm Store per lane resuming from a host-held checkpoint keyed by `(instance, MixEpoch)`, against the same block from a cold Store.

Timing parity requires actual workload and frame count. Record job profiles, resample parameters, worker queue and completion time, device callback wall time, underflows, clock drift, buffer bytes and end-to-end latency. [Verification rules](../architecture/evidence-and-verification.md)
