# UI-01 implementation slices

Proposed sequencing from the pinned app revisions, subject to the architecture workshop and owner approval. Each slice has one owner and observable behavior. [Workspace contract](../contracts/ui.md) · [Acceptance cases](ui-01-acceptance.md)

| Slice | Dependencies | Owner and proposed changes | Exit gate |
|---|---|---|---|
| FW-UI-01 | Phase 0h. Verified framework revision, one egui family per app | Framework maintainers. Add serialized floating-group intent and a checked action to the canonical workspace model. Honor it in the native window path and make panel/window metadata available to input and drop arbitration. Introduce revision-compatible loading. Compile and review typed stubs for presentation, ownership and modal scope before app writers start. | With one eligible group in each mode, changing capability or saved position leaves preference and return slot intact. Unclaimed input is distinguishable from a consumed event after widget blur. Native window monitor-fit and fallback tests run separately. |
| EC-UI-PORT | Phase 3. FW-UI-01 | EffectCraft UI. Inventory existing `dock.rs`, `dock_ui.rs`, `workspace_state.rs`, menus and ScriptUI body placement. Map these to the common Craft API. Keep viewer, timeline and panel commands in the app. Verify the port on built-ins before switching the plugin adapter. A single active dock path owns each state. | Compare all affected layout, modal, focus, IME and Window states with the pinned main app using the port kit. An old saved layout round-trips to the migrated layout with its placement choices intact. |
| EXT-UI-01 | Phase 3. Identity schema, Principal process and permission admission (phase 1) | Shared platform. Add manifest contribution descriptors, instance and mount registry, bounded snapshot channel, UI action receipts and nonblocking teardown. Keep framework dependency out of guest and wire types. Create the small host/SDK fixture with two panels and one dialog through the public contract. | Shared conformance opens two eligible contributions with same-title collisions, rejects cross-owner patches, deduplicates action retries and tears down cleanly on worker death. |
| PC-UI-01 | Phase 3. FW-UI-01, EXT-UI-01, DOC-01 target-bound edits (phase 2) | PhotoCraft UI. Extend lookup at `panels/registry.rs` and realize metadata and body through `panels/panel_docking.rs`. Integrate active/named/remembered layout loading into `dock.rs`, Window/palette state via `app/framework.rs`, modal handling in `app/frame.rs` and inspector contribution in `panels/properties.rs`. | `UI01-workspace`, pass, modal, drop, edit, recovery and save all exercise the normal app entry. Explicit target and linked asset context are correct with a second active document. |
| EC-UI-01 | Phase 3. EC-UI-PORT, EXT-UI-01, DOC-01 target-bound edits (phase 2) | EffectCraft UI. Preserve normal Window command entry and focus restoration in the ported equivalent of `app/window.rs`. Attach registered bodies, typed inspector roles and action termination at canonical dock/slot hooks. Migrate workspace envelopes and legacy placeholders. Port Layer Tools' user workflow to the public SDK proof. | Same fixture and acceptance cases as PhotoCraft, plus locked viewer preview invalidation and prior ScriptUI placement/identity fixtures. |
| UI-01-FREEZE | Phase 3 exit. PC-UI-01, EC-UI-01, UI02-CONTRACT, UI02-FRAMEWORK, UI02-MOUNT, EXT-TOOL, and the Liquify spike limited to UI body and tool capture | Platform and app maintainers. Demonstrate the same public SDK panels, canvases, modals and authorized edit on both apps. Test the stated OS/backend matrix and matching native performance baselines. | Report the full acceptance row results and advertise only verified modes. Compare paired actual work. Built-in and old data preservation gates pass before superseded paths can retire. |

Use the exact PhotoCraft dependency revision as the port API reference. The framework baseline main is a different source line. Before introducing code in EffectCraft, resolve a common revision that provides the new API and verify cargo's resolved facade, transitive framework packages and egui family. The port kit's inventoried component mapping, gap stubs and look/behavior gate apply. The draft plan does not authorize a fork merge, build or checkout change. Once approved, slices branch from the pinned baseline into the owner's arnav-hiwarkar/* forks or Forgejo, never a storytold remote, and builds run only in approved Actions jobs.
