# Threat model for design review

This is the threat and test inventory. All 23 topics are DESIGNED; the [runtime contract](../contracts/runtime.md) (RUN-01/02) defines the grants, identity, generations and execution enforcement, and each mode stays `Unavailable` until its probes pass. Nothing is IMPLEMENTED or TESTED.

| Boundary | Risk | Required mitigation and proof |
|---|---|---|
| Package to supervisor | Malformed manifest, duplicate identity, archive escaping its destination, excessive entries or output, changed executable bytes after consent | Freeze an admitted release digest and local origin. Use a bounded validator and private immutable resource view. Test directory and archive inputs, symlinks, duplicate/case-colliding names, decompression bounds, change during staging and rollback. |
| Supervisor to guest | Arbitrary OS authority from sockets, process launch, local IPC, inherited descriptors, credentials or env | Execution modes require an enforced offline boundary. Validate guest imports and worker environment. Approve OS confinement per provider and target, including descendants. Treat beta's unconstrained native launch as historical only. |
| Guest to app operations | Class-level permission admits actual target outside grant, implicit active target switches, macros use unclassified leaf ops, plugin calls CLI/MCP as host | Resolve capability and target before admission. Preserve plugin provenance through nested calls, command rewrites and broker requests. Recheck immediately before publication. Prove denied command, wrong document with same layer ID, nested IO and grant race. |
| Guest to file broker | Path escape, object swap, network-backed path or relative asset, mutable link | Scope reads and writes to verified handles and explicit chosen data. Do the work on the authorized object. Resolve dependencies under the same scope and local-only rule. Bound streams and decoder work. Exercise alias, moved target, path swap and nested remote reference. |
| Guest to framework | UI impersonates trusted prompt, steals focused viewport, forges consent or synthetic input, leaks stale preview descriptions | Keep attributed chrome and trusted prompt/picker/recovery in the host. Admit raw input once, stage effects after modal resolution, invalidate visual and accessible bound resources on revocation, verify custom and HTML hierarchy. [UI-01](../decisions/ADR-UI-01.md) · [UI-02](../decisions/ADR-UI-02.md) |
| Guest to GPU or render scheduler | Work expansion, resource retention, forced device loss, mismatched result semantics, stale preview publication | Budget and validate submitted resource descriptors and actual work. Keep generation and grant on lease and result. CPU fallback or honest render failure. Device reset has separate recovery outcome. Test against bounded malicious inputs and provider failures. |
| Guest worker stall or loss | UI wait, audio underrun, cancellation lost behind queue backlog, unbounded restarts or retained resources | Runtime handles fatal supervision independently of frontend. Bound per-package and global work, reserve terminal events, use deadline and epoch cancellation, preserve prior committed state. Measure responsiveness with no worker replies. |
| Project and saved workspace | Newer state discarded, reopened dependency auto-executes, downgrade clobbers, preview mistaken for exact output | Persist opaque state and checksummed assets under the application format, with explicit missing/degraded state. Block activation from saved work. Test older writers, failed upgrades, autosave and exact export coverage. |
| Fonts and text | `text.fonts()` or missing-font substitution reaching `craft-font-store` (Google Fonts over HTTPS) or an OS on-demand font download | `text.fonts()` lists installed fonts only. Font install or download is a `Net` sink, never admitted under a plugin chain. Substitution never downloads, and no font bytes reach the guest. `TEXT-missing-font`, `NET-matrix`. |
| Local jobs and other plugins | Scope escalation via installed assistant/service, write persists after failure, revocation races background completion | Establish explicit caller and target delegation, propagate provenance, split document edits from external publication, account exactly what was committed. Verify cancellation, restart, and one-sided publication. |

## Accepted residual risks

- **Shared GPU provider.** ADR-RUN-01 rejected one shared process for all principals because an escape would cross principals. The GPU provider is that shared process for GPU work: one per app per device, with a per-principal logical device for each principal. A provider or driver escape could cross principals. This is accepted because per-principal GPU processes would multiply driver contexts and memory. Proof: `GPU-xprincipal`.
- **CEF inner sandbox off.** The HTML process runs CEF with its inner Chromium sandbox off; our OS confinement of the whole CEF tree (seccomp/Landlock, seatbelt, LPAC) is the boundary. CEF comes only from a bundled or user-picked local archive, is never downloaded, and its install is a `Setting(SecurityRelevant)` sink. Proof: `NET-cef-webrtc`, `CEF-no-windowserver`.

## Platform evidence to resolve in RUN-02/04

Wasmtime documents that the embedder decides which host imports exist. It does not by itself prove a host deputy cannot access the network. AppContainer defines capability-based isolation and network rules for Windows. Landlock availability and access rights depend on the running ABI and kernel. macOS App Sandbox requires entitlement and helper design evidence under the signed application. The older beta's profile source and loopback/write probe cover specific cases on a specific launch route. The workshop has run none of these provider tests. [Wasmtime security](https://docs.wasmtime.dev/security.html) · [Microsoft AppContainer](https://learn.microsoft.com/en-us/windows/win32/secauthz/appcontainer-isolation) · [Linux Landlock](https://docs.kernel.org/userspace-api/landlock.html) · [Apple App Sandbox](https://developer.apple.com/documentation/security/app_sandbox)

The threat model covers actions the platform and workers can cause. Data already read before revocation cannot be recovered from the old process. Killing and re-epoching the affected execution instance, invalidating caches and invalidating all outstanding permission-bound results are required. User-driven later copying or exporting from another application falls outside host process enforcement.
