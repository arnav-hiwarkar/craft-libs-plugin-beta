# Persistent extension instance contract

Designed in [DOC-02, DOC-03 and DOC-04](../decisions/ADR-DOC-02.md), with implementation and runtime gates pending. [Invocation and publication](operations.md) · [Acceptance cases](../implementation/document-acceptance.md)

## Records and participation

One versioned extension record attaches to an app-owned object or occupies a native extension variant. The host owns placement, IDs, standard transforms, masks, blend, locks, hierarchy and history. The record carries stable type and instance identities, state format/version, opaque bytes with bounded length, typed properties, host-owned reference operands, a closure of referenced assets and the provenance `Chain` of its authors. Runtime resolution and cached frames are derived data. They cannot change document equality, history or authored state when a package is missing, unloaded or updated.

```text
ExtensionRecord = (InstanceId, TypeKey, SchemaVersion, BoundedStateBytes, Properties,
                   ReferenceSlots, AssetRefs, SharedContent?, ChildOverrides, BakeRef?, Provenance(Chain))
TypeKey = (PackageId, LocalTypeId)        resolved through craft-idmap, including legacy.<app>.<id>
TypeDecl = (TypeKey, SchemaVersion, AttachmentRole, PropertySchemas, ReferenceSlots, ChildRoles)
RefOperand = Ref(SlotKey)
AssetRef = Embedded(Digest, Size, MediaKind) | Linked(LinkDescriptor, ExpectedDigest?)
BakeKey = (ReleaseDigest, TypeKey, SchemaVersion, ExecProfile, input digests, format/colour/quality,
           time, region, output hash)
```

The shared record lives in CL `plugin-api::doc`, which is dependency-free. A record binds to a provider by `PackageId + TypeKey + SchemaVersion`. `LineageKey` is host-local and never persisted, so lineage adoption governs only data folders and grants, never whether a record is live. An unknown provenance key makes the document read-only ([SDK contract](sdk.md#schema-and-levels)). App formats own encoding. Writers publish through `craft-files` and return its `Receipt` ([file contract](io-jobs.md#publication)). Derived runtime resolution stays in the app registry. A provider derives virtual children with stable keys inside the parent instance. They can be selected, targeted and linked through the parent's generation plus their child key. Host-owned transform, visibility and property overrides, including supported animation, persist when the provider is absent. Expand to Layers uses a normal edit.

An attachment descriptor names the roles it participates in and the scope each requires. A layer source, filter, adjustment, track, clip, transition or geometry object has a negotiated role, schema and provider. The app maps each promised role through render, selection, invalidation, history, import and export. Missing providers render an attributed inert or last-validated preview state and preserve normal layer placement. A compiler match audit alone cannot prove role coverage. Track and timing capabilities depend on the timed evaluation design.

## Transfer and data lifetime

Resolve destination IDs for all objects, instances, properties and shared-content groups before inserting or rewriting references. Defaults, dynamic values, animation keys and expressions use stable host reference operands. Opaque state can retain the operand key across remap. Keep an unresolved descriptor if a destination object is missing and never resolve a coincident ID in another document. Duplicate, linking, paste/import and app load all call the same transfer rule for the full closure. Ordinary duplicate creates a distinct placed instance and follows the owning app's explicit shared-content policy. Embed needed assets by digest once. Native Undo/history, async render and save leases retain their own specifiable committed revisions.

Asset records may name embedded bytes or a host-resolved link. The project carries a portable locator or opaque link identity and expected digest. It carries no permission grant. Access is authorized anew against current scope. Validate metadata without resolving addresses when opening or transferring. At use, broker the actual file identity, verify its expected digest while reading and recheck authorization before delivery or publication. A user can relink to a current file or embed the locally granted asset. Live leases and persisted project generations protect their reachable blobs. Reclaim unreachable staging data only when publication/recovery cannot reference it.

## Open, migrate and write

Open parses bounded host envelope and record headers and validates authored bytes and reference structure without guest execution. Bind compatible already-enabled providers after the project has loaded. A missing or unsupported schema/type remains inert, with typed metadata and raw bytes intact. A known host header preserves unrecognized provider bytes exactly, including across allowed placement edits. A future host header that prevents proving complete asset and reference closure permits a read-only view where possible, or refusal. The user can make a byte-preserving copy or explicitly export a compatible representation. Missing or corrupt authored bytes are distinct from a missing provider. Keep the original bytes and report an incomplete closure before a repair save. Unknown JSON values cannot stand in for opaque bytes.

Migrations inspect admitted state and assets under restricted capabilities. Stage the candidate and assets through `edit.commit` against the original document's read set and provider `ReleaseDigest`, validate output, retain the old history state, and publish one Undo. Failure leaves the original payload and old provider requirement unchanged. Update of a package and update of a document payload are different actions. Revoke and cancellation poison pending migration work.

The common native writer selects a readable file version from all retained content, including absent or newer records, for normal, copy, Collect, incremental and recovery saves. An older reader unable to retain all bytes refuses the incompatible version and cannot overwrite it through normal open/save. Only explicit export or bake operations choose a lossy representation. Project upgrades and autosaves use the same envelope rule. Native save commits authored state even if optional appearance generation fails and reports that outcome.

- EffectCraft's writer keeps the native text representation when there are no reachable embedded extension assets. Extension records raise its required schema. With embedded extension assets it writes a self-contained ZIP with `format.json`, `project.json` or `project.xml`, and digest-keyed members in `blobs/`. Recognize the archive in the same open, import and recovery reader. An older build refuses the archive instead of opening an incomplete document. Use binary opaque state with a bounded base64 representation in text. Portable Collect embeds the authorized extension links; collecting external links separately requires explicit user selection and reports each published file.
- PhotoCraft writes the stable host header into the native manifest and binary state to its existing bounded object store. Use format-version refusal on insufficient older readers. Use the same typed record for Smart Filter, adjustment and first-class attachment support.
- Capture immutable revision and blob closure for every destination. Stream bounded entry counts, size, depth, declared and actual expansion and digest verification off paint. Refuse ambiguous or duplicate members. Serialize publication for a destination. A newly accepted revision cannot be overwritten by a late older save. The writer calls `craft-files` and returns its one `Receipt`: `Unchanged` for pre-replacement failure, `VisibleUnconfirmed(reason)` for a visible publication whose durability barrier failed, and `Durable` for confirmed durability, with the published revision. Saved/recovery markers name that revision and observed durability. Desktop staging, exchange and directory durability belong to `craft-files`. Browser storage/download reports `VisibleUnconfirmed(Browser)`. Every autosave generation embeds its complete closure.


## Typed properties and render provenance

Props use stable per-type keys and versioned kinds, units and constraints, with compatible default and interpolation rules. EC exposes normal keyframing, parameter groups, expressions, layer references and links through its existing typed property owners. PC Properties and Smart Filter UI bind live non-destructive authored state. Each host advertises only implemented animation families. Evaluate structural and runtime dependencies under bounded work. A same-time cycle fails. A temporal recurrence is admitted only with an explicit horizon, base case and stable checkpoints. Feedback cycles strictly reduce the canonical resolved step toward that bound. See the [timed evaluator](time.md#time-mapping-and-evaluation). Acyclic future reads are permitted. Charge expanded work and detect recursion by instance, port and resolved time. RENDER-03 specifies exact time keys and interpolation behavior across discontinuities.

Key engine caches and extension preview frames by the one `CacheKey` ([render contract](render.md#composition-and-export)): resolved `ReleaseDigest`, type/state and validated reads, inputs, applicable properties, format/color/alpha, quality, time, scale and coverage. EffectCraft's existing missing-effect skip and PhotoCraft's current Smart Filter pass-through need explicit incomplete outcomes. A preview may show a labeled placeholder or known last-good result using its applicable scope. An exact file output requires complete results for the requested scope from every needed stage. Use an exact bake only with host-produced verifiable provenance for capture purpose and the full `BakeKey`. `BakeKey` is the only durable bake identity; the render and SDK contracts reference it. Match current scope and complete coverage against the actual request. Imported unverified bake metadata can support a labeled preview, or explicit flattening into authored pixels. Separate optional native appearance from exact outputs. A failed optional composite does not discard the editable document. A stale cache or unverified authored bake claim cannot certify exact output. Explicit flatten or bake can turn a chosen result into a new authored object. Preserve the original source under the app's normal Undo/save/import rules.
