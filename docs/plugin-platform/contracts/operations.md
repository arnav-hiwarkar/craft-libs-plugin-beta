# Input-to-edit invocation contract

Designed in [UI-03, UI-04 and DOC-01](../decisions/ADR-UI-03.md), with execution tests pending. [Workspace admission](ui.md) · [Prepared content](ui-content.md)

```text
ToolSpec = (ContributionKey, ViewKind[], Claims, TransformPolicy, InputProfile, OverlayRoles)
Capture = (View, Viewport, Device, InteractionEpoch, Principal, LiveDoc, ResolvedTargets, ReadSet, DocRevision)
Sample = (Sequence, MonotonicTime, TransformGeneration, PointOrRay, Pen?, Modifiers)
Gesture = Begin(ContextTicket) | Samples(Sample[]) | End(LastSequence) | Cancel(Reason)
OperationDescriptor = (Id, Version, TypedSchema, TargetResolver, EffectKind, HookPolicy)
QueryOpen = (ContextTicket, ResolvedTarget, Projection, Filter, Order, Time?, Selection?)
ReadSet = {ReadKey → O(1) token}         recorded under every ticket and job
Commit = (ContextTicket, IntentId, UndoLabel, Operation[])      checked against the ticket's ReadSet
CommitOutcome = Committed(Receipt) | Stale(ReadKey[]) | Expired | Revoked | Failed(OpError)
doc.list(ticket) -> DocRef[]                 open documents the chain may read
doc.ticket(DocRef, reason) -> ContextTicket  minted from the user chain, with its own ReadSet
res.<kind>.list|get|add|update|remove@1      host resource libraries, entries carry Provenance(Chain)
input.device(grant) -> DeviceStream          user-picked HID or MIDI
capture.open(grant) -> CaptureStream         brokered camera, screen or microphone frames and AudioBlocks
```

## Capture and preview

Register supported tool families through the host's regular tool selector. One active tool owns each view. Protected host controls and momentary navigation are resolved before capture; passive overlays cannot take a drag. Intersect claimed regions with app-approved hit areas. Only the host can classify a navigation gesture that is allowed while a modal is active. The host uses prepared hit and snap indexes, native indicators, brush footprint, marquee and local gizmo feedback. Modifier changes may adjust declared constraints within the active capture. Work beyond local feedback can use async render or analysis. Host capture retains the originating viewport/device and document incarnation, explicit object/layer/mask IDs, its read set, base `DocRevision` for previews and the `PrincipalEpoch`. Sample coordinates use the origin and its transform generation. A fixed-basis capture preserves the chosen document plane or camera and cancels on incompatible rebind. Adaptive samples carry their transformed point or ray and generation.

Reserve ack window, sample memory and terminal capacity before Begin. Read only current-pass input and route each claim once. Keep latest replaceable motion. Preserve every sample for fidelity-required traces or cancel on overflow with a visible result. End seals the host-observed tail and carries the final sequence and ends physical capture. Owner barrier cancellation before End admission replaces it with Cancel. After End the pending edit owns a distinct cancellable lifetime. Modal blocking, expiry, unmount, target or grant invalidation terminates pending work without duplicating the input terminal. Never wait on a paint worker at release. Verify contiguous receipt of all required samples before accepting a prepared result. A pending action supplies complete ordered samples and a matching target and read set when it publishes.

Add an overlay at a declared stage on the owning viewport, in deterministic app-role, user-order and stable-key order. Keep viewport-qualified previews outside committed and exact/export state. Scope preview leases to view, capture, incarnation, base, preview generation and authority. Invalidate before cancellation, committed repaint and detached-view rebind. A late preview cannot enter a visible cache. Headless keeps compatible explicit operations and queries, with UI-only capture unavailable.

## Commands, hooks and events

One app command catalogue advertises typed operations, state and shortcuts. Stable plugin keys enter palette, menus, context, toolbar and declared contribution slots. The user's context-aware keymap resolves conflicts. One user-selected replacement owns an eligible slot, with visible failure and explicit fallback policy. Host restore reaches the built-in directly. Veto, replacement, wrapping, disclosure and observation are distinct authorities. Protected services and prompts use host-owned policy.

Hooks execute in cancellable async preparation with a deadline and fixed lineage. Resolve an invocation's actual targets before showing scoped/projection-compatible argument data to a hook. Bind once-used continuation to schema, invocation, chain index, allowed effect envelope and scope. Re-resolve targets after rewrites. Retain author provenance for every surviving change; recheck grants of all relevant participants on publication. Execute approved prestages without blocking paint or an audio callback. A timed-out optional wrapper follows the declared admitted fallback. An unavailable selected replacement reports a result and uses built-in only when configured. Use a causal ID, bounded depth/work and visited route keys across nested commands and follow-ups. Hooks cannot use public reentry or act as a deputy for denied data or side effects. Bind host-issued provenance to every nested command, Action, legacy callback and deferred job. Resolve every effective leaf after parameter and playback substitutions, including implicit reads, deferred launches and frontend effects. Reapply admission at the real sink. User confirmation and built-in fallback retain original lineage; neither restores denied authority. Use typed local equivalents for reachable command behavior under the offline rule.

Open/close/save, selection/tool and committed document changes use a scoped, ordered outbox. Render lifecycle includes one job-correlated terminal. Playback, dirty signals and progress may coalesce as timestamped latest-value streams. Each subscription has quotas. On ordered-event overflow, stop deltas and return a gap. Publish outbox records before waking observers. Obtain a scoped immutable snapshot and opaque watermark at the same owner cut, bound to subscription generation, projection, scope and grant. Resume strictly after it against bounded retention, with stable delivery IDs. Recheck live authority immediately before handoff. Require another cut if the watermark expired. Keep receipt retrieval separate from subscriptions. Follow-up edits are new authorized invocations with inherited cause. Layer/selection/project events can never mint edit authority on their own.

## Query and publication

`query.open` returns a bounded immutable snapshot lease. It fixes target/object incarnation, revision, evaluated time and selection as needed. A lease opened under a ticket or job adds its (projection, filter, collection fingerprint) token to that read set. `query.page(lease, cursor, budget)` returns a typed projection and opaque cursor, including a continuation for empty but unfinished scans. Bound live lease count and bytes, examined rows/evaluations and serialized bytes separately. Slice geometry, masks and key lists and use indexed projection where appropriate. A nonactive composition resolves its own time. Revalidate authorization on offer and delivery. Revoke, close, expiry, schema mismatch and resource exhaustion have explicit outcomes. Shared buffers expose bounded brokered read leases. Already delivered copies count as disclosure. Recheck immediately before any new lease or buffer handoff.

`edit.commit(ticket, intent, label, ops)` admits resolved document-only operations and preparatory IO through separately brokered capabilities. All changes stage in one engine-owned candidate. Operation reads see earlier staged writes. Preparation stages failure-prone allocation, checks and bookkeeping away from paint. Each ticket and job records a read set (ReadKey → O(1) token) covering captured targets, query leases opened under it, render reads and write targets; publication compares tokens only; mismatch returns Stale(ReadKey[]) with no Undo; DocRevision scopes previews and receipts only. At the owner publication point, also recheck target, caller and grants under the current `PrincipalEpoch`, pending action lifetime and explicit history ownership. Optional editor-only time or selection effects use separate state generation preconditions. A ticket retried after receipt eviction returns `Expired`. Never replace all editor state from a stale fork. Reserve bounded commit work, history, receipt and outbox capacity before publication. Publish the new state and authoritative history/receipt/outbox as one decision. Only the explicit atomic parent may publish or record an Undo. Its children stage into that parent. Historical non-atomic actions use distinct leaf authorization and outcome records. The owner serializes this with revocation and rejects late or duplicate effects. No-op changes have no Undo. Disk/file effects have separate stage and publication outcomes and never enter document history.

## Documents, resources and devices

A ticket binds one document and cannot be retargeted. `doc.list(ticket)` returns the open documents the chain holds a read grant for. `doc.ticket(DocRef, reason)` mints a ticket for one of them from the user chain that started the invocation, with its own read set; a plugin alone cannot mint one. Each document commits separately with its own Undo and receipt, so a batch across open documents reports one outcome per document. `doc.open` remains the route for files.

Host resource libraries (brushes, patterns, gradients, swatches, LUTs and tool presets) are typed Domain operations, or App operations with `why_not_domain` where only one app has the kind. Every entry carries `Provenance(Chain)` and replays under its author chain like any persisted artifact. A library write is an app-settings effect with its own receipt, not document history. Placing an entry into a document uses the normal transfer rule.

`input.device(grant)` delivers events from a user-picked HID or MIDI device. OSC is network and is excluded. `capture.open(grant)` delivers brokered camera, screen or microphone frames as read leases and audio as `AudioBlock`s. Both grants come only from a host picker. The app process opens the OS device; principal processes stay denied AV devices. Revoke closes the stream. These ship in phase 6.
